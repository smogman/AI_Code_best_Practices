## What Things Actually Cost

Community data from practitioners suggests ~$13/developer/day for active Claude Code use. This varies widely based on workflow. Understanding what drives cost lets you optimize the right things.

### High-cost actions
- Reading large files repeatedly across sessions (the same file, session after session)
- Verbose bash output dumped into context
- Long back-and-forth correction loops
- Running Opus on tasks that don't need it
- Large `CLAUDE.md` files read every session

### Low-cost actions
- Targeted file reads (specific functions, not whole files)
- Compact summaries and structured output
- Short, focused sessions
- Using Haiku for simple tasks

## Model Tiers and When to Use Each

| Model | Cost | Best for |
|---|---|---|
| Haiku | Cheapest | Simple edits, boilerplate, small fixes |
| Sonnet | Mid | Most daily work: implementation, debugging |
| Opus | Most expensive | Complex reasoning, architecture, multi-file planning |

The default is usually Sonnet. A practical optimization: use Opus for the planning phase of complex tasks, then switch to Sonnet for implementation.

```
> /model opus
Plan the refactor of the authentication module.
[Review plan]
> /model sonnet
Execute the plan.
```

## The `CLAUDE.md` Size Tax

Every session starts by reading your `CLAUDE.md`. A 500-line file costs 5× more per session than a 100-line file, and as covered in 201, it also degrades instruction-following.

Keeping `CLAUDE.md` lean is both a quality practice and a cost practice.

## Prompt Caching: The Numbers

Prompt caching stores the computational work for unchanged content at the beginning of each API call. Claude Code loads the same system prompt, CLAUDE.md files, and conversation history on every turn. All of that gets cached.

Community benchmarks from practitioners:

- Well-optimized active sessions achieve **~90% cache hit rates**
- A 20-turn session with 100K stable context tokens saves **84% in input costs** vs. no caching
- Batching related work in one session is **3.8x cheaper** than the same work spread across five sessions
- Cached input tokens cost **10% of uncached** (a 10x difference)

Cache TTL varies by plan: **Max subscribers get 1-hour TTL**, Pro and API users get **5-minute TTL**. The timer resets on each cache hit during active work.

Structure your sessions so stable content appears first:
1. `CLAUDE.md` (stable, cached)
2. Project context (stable for a session, cached after first use)
3. The specific task (variable, not cached)

**Three actions that destroy your cache:**
- Switching models mid-session (caches are model-specific: Opus and Sonnet cannot share)
- Using `/rewind` (breaks the cache on all content after the rewind point)
- Installing MCP servers mid-session (rebuilds tool definitions, invalidates all downstream caches)

Decide your model before the session starts. If you need to switch, start a fresh session instead.

For automated pipelines with the API, place stable content (instructions, context) before variable content (the current task) in every call.

## The Session Length vs. Quality Trade-off

There's a cost to long sessions beyond tokens: quality degrades. Short, focused sessions often cost *less* and produce *better* results than a single long session.

This is counterintuitive but well-supported by community experience. The efficiency of a fresh context is real.

## Parallelism Cost Considerations

Running 10 parallel agents costs 10× per minute, but finishes the work faster. Whether this is cost-effective depends on:

- Is the time savings worth the cost multiplier?
- Do the tasks truly parallelize (no dependencies)?
- Is the quality improvement from context isolation worth it?

For most teams, 2-4 parallel agents on truly independent tasks is the sweet spot.

## Budgeting for Teams

Practical approaches teams use:
- Per-developer monthly budget with soft alerts
- Cost tracking by project or feature (correlate spend to output)
- Scheduled batch processing overnight for non-urgent tasks (can use less expensive models or off-peak pricing)
- Reserving Opus for PR review and architecture, Sonnet for everything else

## Measuring What You're Actually Spending

Use `/cost` regularly to build intuition:

```
> /cost
```

Run it before and after different types of tasks. You'll quickly develop a sense for what's expensive in your workflow, and it's often not what you'd expect.
