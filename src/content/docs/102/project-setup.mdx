Do this once per project. A well-set-up project means every session starts faster and Claude makes fewer mistakes.

## The Checklist

### 1. Verify your `.gitignore` is solid

Claude Code can read your files. Make sure secrets and generated files are excluded before Claude scans your project.

Check these are ignored:
- `.env` and `.env.local`
- `node_modules/`
- Build output (`dist/`, `.next/`, etc.)
- Any files containing API keys or credentials

### 2. Create `.claude/settings.json`

Pre-approve the commands you'll use every session so Claude doesn't prompt you for them.

```json
{
  "permissions": {
    "allow": [
      "Bash(npm test)",
      "Bash(npm run lint)",
      "Bash(npm run typecheck)",
      "Bash(npm run build)"
    ]
  }
}
```

Commit this file. Your whole team benefits from it.

### 3. Write your `CLAUDE.md`

See the [CLAUDE.md Basics](/AI_Code_best_Practices/102/claude-md-basics/) lesson. At minimum include your stack, key conventions, and the commands from step 2.

### 4. Make sure your test suite runs cleanly

Before using Claude Code seriously on a project, confirm `npm test` (or your equivalent) passes from a clean state. Claude will run your tests to verify its own work. If tests are already broken, it can't tell whether it caused new failures.

### 5. Check that your linter is configured

A linter gives Claude immediate feedback on code style. If you don't have one, now is a good time to add ESLint/Prettier or whatever fits your stack.

### 6. Commit the setup files

```bash
git add .claude/settings.json CLAUDE.md
git commit -m "Add Claude Code project configuration"
```

Your teammates can now use Claude Code with the same settings.

## Optional but Recommended

**Add a `.claude/` entry to `.gitignore` exceptions.** By default `.claude/` might be gitignored on some setups. Make sure `settings.json` is tracked.

**Create a scratch branch.** For your first few sessions on a new project, work on a branch. Claude's changes are easy to review and discard with `git diff` and `git checkout`.

**Note your architecture in CLAUDE.md.** A two-sentence description of how the app is structured saves Claude significant exploration time at the start of each session.

## Quick Verification

After setup, start a session and run this as your first prompt:

```
What do you know about this project? Summarize the stack, main commands, and any constraints from CLAUDE.md.
```

Claude's answer tells you immediately whether it absorbed your configuration correctly.
