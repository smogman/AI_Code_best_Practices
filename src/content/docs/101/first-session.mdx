## Starting a Session

Navigate to your project root and run:

```bash
claude
```

Always run Claude from the root of your project — it needs to see the full directory structure to understand your codebase.

## Prompting Patterns That Work

### Be Specific About What You Want

Vague prompts get vague results.

| Instead of... | Try... |
|---|---|
| "fix the bug" | "The login function in `src/auth.ts` throws a null reference error when email is empty. Fix it." |
| "add a feature" | "Add a `deleteUser(id)` function to `src/users.ts` that removes the user and their associated posts from the database." |
| "clean this up" | "Refactor `processOrder()` in `src/orders.ts` — it's doing too many things. Split it into smaller functions." |

### Give Claude the Full Picture

Claude only knows what's in the conversation. If a bug requires understanding three files, tell it which three files matter. If there's a constraint it should know about, say it upfront.

```
The checkout flow lives in src/checkout/. The issue is in CheckoutForm.tsx — 
when a user clicks "Pay" without filling in their address, the form submits 
anyway instead of showing validation errors. The validation logic is in 
src/utils/validation.ts.
```

### Ask One Thing at a Time

Multi-part requests dilute focus. Claude is better at "fix the null check in auth.ts" than "fix the null check, add tests, update the README, and refactor the helper functions."

The session is stateful — do things in sequence rather than stacking them.

## Reading Claude's Output

Claude will typically:
1. **Explain what it's about to do** — read this before approving anything
2. **Show you the changes** in a diff-like view
3. **Tell you what it did** after completing

If something looks wrong at step 1, say so before it proceeds. It's easier to redirect than to undo.

## Giving Feedback Mid-Session

You don't have to wait for Claude to finish. If it's going in the wrong direction, interrupt with a correction:

- *"Wait — don't add error logging, just fix the null check."*
- *"That's not right. The issue is in the `processPayment` function, not `validateCart`."*
- *"Good, but use `const` not `let` for that variable."*

Claude will course-correct. Repeated corrections in a long session can dilute the context (covered in 201), but a few redirects are fine.

## Ending a Session

Type `/exit` or press `Ctrl+C`. There's nothing to save — changes Claude made to your files are already on disk.

<Exercise title="Have a productive debugging session" time="20 min">

**Task:** Find a real bug or rough edge in a project you're working on and fix it with Claude.

**Steps:**
1. Open a project with a known issue (or pick one file you want improved)
2. Start a Claude session from the project root
3. Describe the problem specifically — include the file name and what's going wrong
4. Let Claude propose a fix, then approve or redirect it
5. Verify the fix works

**Success Criteria:**
- [ ] You described the problem without Claude asking clarifying questions
- [ ] Claude found the right location in the code on the first try
- [ ] The fix works (run the code or tests to confirm)
- [ ] You didn't need to copy-paste anything — Claude edited the file directly

</Exercise>
