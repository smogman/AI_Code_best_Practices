## What Hooks Are

Hooks are shell commands configured to run automatically at specific points in Claude's workflow. They automate rules like "always run the linter after every file edit." No asking required.

They live in `.claude/settings.json`.

## Hook Events

| Event | When it fires |
|---|---|
| `PreToolUse` | Before Claude uses any tool (read, edit, bash, etc.) |
| `PostToolUse` | After Claude uses any tool |
| `Stop` | When Claude finishes a response |
| `Notification` | When Claude sends a notification |

## Hook Structure

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit",
        "hooks": [
          {
            "type": "command",
            "command": "npm run lint --fix"
          }
        ]
      }
    ]
  }
}
```

This runs `npm run lint --fix` every time Claude edits a file.

## The Matcher

The `matcher` field filters which tools trigger the hook. Common values:

- `"Edit"`: fires on file edits
- `"Bash"`: fires on bash commands
- `"Read"`: fires on file reads
- `""`: fires on everything (no filter)

You can also match on specific patterns using regex.

## Practical Hook Examples

### Auto-lint on edit
```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit",
        "hooks": [{ "type": "command", "command": "npm run lint --fix" }]
      }
    ]
  }
}
```

### Security check before writing sensitive files
```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Edit",
        "hooks": [{
          "type": "command",
          "command": "echo 'Checking for secrets...' && grep -rn 'password\\|secret\\|api_key' $CLAUDE_TOOL_INPUT_PATH 2>/dev/null || true"
        }]
      }
    ]
  }
}
```

### Log all bash commands Claude runs
```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [{
          "type": "command",
          "command": "echo \"$(date): $CLAUDE_TOOL_INPUT_COMMAND\" >> ~/.claude/audit.log"
        }]
      }
    ]
  }
}
```

### Run tests after every edit
```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit",
        "hooks": [{ "type": "command", "command": "npm test --silent 2>&1 | tail -5" }]
      }
    ]
  }
}
```

## Hook Exit Codes

If a `PreToolUse` hook exits with a non-zero code, Claude **blocks the action**. This is how you enforce hard rules:

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Edit",
        "hooks": [{
          "type": "command",
          "command": "if echo '$CLAUDE_TOOL_INPUT_PATH' | grep -q 'src/generated/'; then exit 1; fi"
        }]
      }
    ]
  }
}
```

This prevents Claude from editing files in `src/generated/`. Period.

## Blocking Destructive Operations

LLMs handle negations less reliably than positive statements. "Do not delete anything" is weaker than a hook that literally blocks the command.

A documented incident: a developer asked Claude to remove old compressed files from an archive directory, explicitly writing "do not remove any data." Claude deleted 202GB of archive files. The data was unrecoverable.

The pattern repeats: `rsync --delete` when the intent was `rsync --archive`, `git clean -f` when asked to "clean up" a branch, `rm -rf` when asked to "remove old files."

A `PreToolUse` hook on Bash is the mechanical solution:

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [{
          "type": "command",
          "command": "echo \"$CLAUDE_TOOL_INPUT_COMMAND\" | grep -E '(rm -rf|rm -f|git clean -f|git reset --hard|git checkout -- |rmdir)' && echo 'Blocked: destructive command requires manual approval' && exit 1 || exit 0"
        }]
      }
    ]
  }
}
```

This blocks the specific commands most likely to cause irreversible damage. Claude sees the block, reports what it was trying to do, and waits for you to run it manually.

Add `disableBypassPermissionsMode: "disable"` in your user settings to prevent skip-permissions from removing this safety net.

## Hook Environment Variables

Hooks get context about what Claude is doing via environment variables:

- `$CLAUDE_TOOL_NAME`: the tool being used (Edit, Bash, etc.)
- `$CLAUDE_TOOL_INPUT_PATH`: for Edit/Read, the file path
- `$CLAUDE_TOOL_INPUT_COMMAND`: for Bash, the command being run
