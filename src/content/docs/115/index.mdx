Claude says things with identical confidence whether it is certain or guessing. The code it writes looks right. It often is not. Test-Driven Development is the practice that makes this verifiable instead of assumed.

## Lessons

1. [Why TDD with AI](/AI_Code_best_Practices/115/why-tdd/): the 1.75x error rate, and why Claude's self-assessment is not verification
2. [The TDD Workflow](/AI_Code_best_Practices/115/tdd-workflow/): writing tests first and using them as Claude's feedback loop
3. [Retrofitting Tests to Existing Code](/AI_Code_best_Practices/115/tdd-existing-code/): how to apply TDD when the code already exists

## Prerequisites

Complete 101 and 102. You need a real project with a test runner already set up.

## What You'll Be Able to Do

- Write tests before implementation so Claude has an objective target to hit
- Set up a feedback loop where Claude iterates on failures without your intervention
- Add tests to existing code before modifying it, creating a safety net for changes
